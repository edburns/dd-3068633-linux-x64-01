## Section 7: Failure Analysis

The campaign had no terminal failures: the metadata status is `succeeded`, the exit code is `0`, and both target PRs merged. Two non-fatal execution issues are still useful for improving the shepherd.

### 7.1 Exact-SHA worktree preparation

During stage 30 for [#2](https://github.com/edburns/dd-3068633-linux-x64-01/issues/2), the first isolated validation attempt could not start because the PR commit was not yet present in the local object store. The shepherd fetched the exact commit, created the detached validation worktree, and reran the unchanged canonical command successfully.

**Root cause:** local validation assumed the remote PR HEAD object was already available locally.

**Corrective action:** fetch the exact PR HEAD before attempting detached-worktree creation, rather than treating the missing object as an exceptional retry path.

### 7.2 Path-set serialization mismatch

The first atomic final gate for [#4](https://github.com/edburns/dd-3068633-linux-x64-01/pull/4) stopped because a `jq` path-set comparison expected compact JSON while the command produced pretty-printed JSON. The paths themselves were correct. The shepherd reran the full gate with canonical compact serialization, and no repository or PR state changed.

**Root cause:** a semantic set check depended on JSON whitespace formatting.

**Corrective action:** use `jq -c` consistently or compare arrays structurally inside one `jq` expression.

### 7.3 Review finding on raw stdout cardinality

The first CCRA round on [#4](https://github.com/edburns/dd-3068633-linux-x64-01/pull/4) found that filtering blank lines before a count assertion weakened the exact single-line output contract.

**Root cause:** the test measured nonblank output lines rather than raw stdout records.

**Corrective action applied:** assert the raw captured output count before testing nonblank content and exact text. The follow-up review produced zero comments.

## Section 8: Observations and Recommendations

### 8.1 What worked well

- **Serial dependency handling was correct.** The second task began only after the first PR merged into the campaign base, preserving the intended compatibility contract.
- **Exact-SHA validation was strong.** Both stage 30 sessions ran the repository-owned Pester command against the candidate commit and checked current-SHA workflow results.
- **Review freshness was explicit.** Stage 40 correlated each CCRA review with the current HEAD, preventing an earlier review from satisfying a later gate.
- **Convergence was fast.** Three total review rounds produced only one actionable comment; both tasks ended with zero-comment current-HEAD reviews.
- **Merge gates were fail-closed.** Base branch, mergeability, checks, unresolved threads, review comments, issue linkage, changed paths, and HEAD stability were checked before merge.
- **Control-mode isolation was preserved.** With lesson propagation `off`, no campaign lesson artifacts were read or modified.

### 8.2 What could improve

- The exported sessions account for only 67% of campaign elapsed time (21m08s of 31m26s). Script-level transition timestamps would make orchestration overhead easier to separate from agent work.
- Input and output token values are redacted, preventing token-efficiency comparisons even though AIU is available.
- Stage 30 incurred two avoidable retries on [#2](https://github.com/edburns/dd-3068633-linux-x64-01/issues/2): fetching the exact PR commit after worktree creation failed and correcting a formatting-sensitive JSON comparison.
- The report had no parent-level memory, prompt, or job-log artifacts to correlate with the run. This is acceptable for the control campaign but limits cross-layer diagnostics.

### 8.3 Recommendations

1. **Fetch before validating.** Resolve and fetch the PR HEAD SHA before any detached worktree operation.
2. **Use structural JSON comparisons.** Normalize with `jq -cS` or compare arrays within `jq`; never rely on presentation whitespace.
3. **Record machine-readable stage outcomes.** Add one compact outcome artifact per phase containing start, finish, PR, HEAD, check count, review ID, comment count, and result. This would eliminate repeated parsing of session transcripts.
4. **Expose non-sensitive token aggregates.** Preserve numeric input, output, and cache-token totals in usage checkpoints even when prompts and generated content remain redacted.
5. **Capture transition timing.** Record timestamps between phase exports, task handoffs, and campaign finalization so active agent time and orchestration overhead can be compared directly.
6. **Retain the raw-output review lesson in tests.** Exact stdout contracts should always assert raw record cardinality before filtering or normalization. Because lesson propagation was `off`, this recommendation belongs in the stage skill or test template rather than campaign memory.

Overall, this control run demonstrated reliable end-to-end shepherding: both small, serial PowerShell tasks passed exact-SHA tests and CI, converged under CCRA review, and merged without manual intervention or terminal failure.
